# 需求文档：工作区本地 MCP 上游

## 功能概述

工作区所有者可在 Coding Tools MCP 桌面端保存并管理本机 MCP 配置。首版支持 `stdio` 传输：应用启动已启用的本机 MCP 子进程、通过 MCP 初始化协商取得其工具目录，并把经用户白名单许可的工具作为 Coding Tools MCP 的命名空间工具公开给已认证的远端客户端。配置模型与具体 MCP 实现无关。

## 术语定义

- **上游 MCP**：由桌面端作为 MCP 客户端启动或连接、并将工具转发给远端 MCP 客户端的本地 MCP 服务。
- **工具前缀**：为避免与核心工具或其他上游冲突而附加给上游工具名称的稳定标识，例如 `example__`。
- **工具白名单**：工作区所有者明确准许暴露的上游工具原始名称集合；未列入的工具不可被远端发现或调用。

## 范围边界

**In Scope**

- 每个工作区保存多个本地 MCP 配置，并能新增、编辑、启用、停用和删除。
- 支持 `stdio` 配置：`command`、`args` 和 `env`。
- 随本应用 MCP 运行时启动、初始化、转发、停止和重启已启用的上游。
- 把白名单工具以稳定前缀公开到现有 `/mcp` 的 `tools/list` 与 `tools/call`。
- 在工作区页显示配置、运行结果、白名单与通用配置说明。
- 对配置、启动、协议、白名单和名称冲突提供可理解的错误信息和测试。

**Out of Scope**

- HTTP、SSE、WebSocket 或远程上游 MCP 传输。
- 自动导入 Codex、Claude 或其他应用的 MCP 配置文件。
- 将上游 MCP 的环境变量、进程标准错误或凭据发送给远端客户端。
- 自动允许上游发现的全部工具；空白名单不公开任何上游工具。
- 对上游 MCP 的 OAuth 登录、安装、升级或多用户授权。

## 需求列表

### FR-1：持久化工作区上游配置

**优先级:** Must

作为工作区所有者，我想为工作区配置一个或多个本机 stdio MCP，以便它们能够在本应用启动 MCP 服务时一同运行。

#### 验收标准

1. WHEN 用户保存有效配置 THEN 系统 SHALL 将唯一 ID、显示名称、启用状态、传输类型、命令、参数、环境变量和工具白名单随工作区持久化。
2. WHEN 用户重新打开工作区 THEN 系统 SHALL 恢复已保存的上游配置且不丢失参数或环境变量。
3. IF 配置的传输类型不是 `stdio`、命令为空、工具前缀无效或白名单名称重复 THEN 系统 SHALL 拒绝保存并指出字段问题。
4. WHEN 用户删除配置 THEN 系统 SHALL 将其从工作区移除；若当前 MCP 运行时正在运行，系统 SHALL 先以安全方式重启运行时再完成删除。

### FR-2：桌面端配置体验

**优先级:** Must

作为工作区所有者，我想在桌面端维护上游配置和允许的工具，以便不必手改配置文件。

#### 验收标准

1. WHEN 用户进入工作区 MCP 配置区 THEN 系统 SHALL 显示各上游的名称、启用状态、命令、工具前缀和白名单数量。
2. WHEN 用户新增或编辑 stdio 上游 THEN 系统 SHALL 提供命令、参数列表、环境变量键值对、工具前缀和工具白名单的表单。
3. WHEN 用户新增上游配置 THEN 系统 SHALL 提供通用字段，但 SHALL 不写入任何未确认的本机路径或环境变量。
4. WHILE 白名单为空 THEN 系统 SHALL 明确提示该上游启动后不会向远端暴露工具。

### FR-3：上游 MCP 生命周期与协议

**优先级:** Must

作为远端 MCP 客户端，我想使用已启用的本机 MCP 工具，以便 ChatGPT 或云端 Codex 能通过本应用完成本机开发工作。

#### 验收标准

1. WHEN 本应用 MCP 运行时启动 THEN 系统 SHALL 为每个启用的 stdio 配置以已保存的命令、参数和环境变量启动一个独立子进程。
2. WHEN 子进程启动 THEN 系统 SHALL 发送 MCP `initialize` 请求、等待有效响应，再发送 `tools/list` 请求。
3. IF 初始化、工具发现、进程退出、超时或标准输出协议解析失败 THEN 系统 SHALL 使本次 MCP 启动失败，记录不含环境变量值的诊断日志，并在桌面端显示可操作错误。
4. WHEN 本应用 MCP 运行时停止、重启或工作区被删除 THEN 系统 SHALL 关闭上游输入、请求进程退出并在必要时终止其子进程。

### FR-4：工具目录与调用转发

**优先级:** Must

作为已认证的远端 MCP 客户端，我想在工具目录中看到允许的上游工具并调用它们，以便使用本机工具链。

#### 验收标准

1. WHEN 远端调用 `tools/list` THEN 系统 SHALL 保留核心工具，并附加每个已初始化上游白名单中的工具。
2. WHEN 上游工具公开 THEN 系统 SHALL 使用 `<prefix>__<原始名称>` 作为唯一工具名，同时保留原始描述和输入 schema。
3. WHEN 远端调用公开的上游工具 THEN 系统 SHALL 移除工具前缀、将参数原样转发为上游 `tools/call` 请求，并把上游 MCP 结果映射为当前服务的标准工具结果。
4. IF 远端调用未公开、未知、停用或不健康的上游工具 THEN 系统 SHALL 拒绝调用，且不得向上游发送请求。
5. WHILE 现有 OAuth、Bearer 或无认证策略生效 THEN 系统 SHALL 在转发前执行现有的外层认证和权限边界。

### FR-5：安全边界与可观测性

**优先级:** Must

作为工作区所有者，我想限制远端可调用的本机能力并诊断问题，以便安全地对外开放工作区。

#### 验收标准

1. WHEN 上游配置被保存或记录日志 THEN 系统 SHALL 不在远端 MCP 响应、普通运行日志或 UI 摘要中显示环境变量值。
2. WHEN 白名单或前缀与其他已启用上游或核心工具发生冲突 THEN 系统 SHALL 拒绝配置或运行时启动，并明确冲突名称。
3. WHEN 上游请求完成 THEN 系统 SHALL 在工作区日志中记录上游 ID、公开工具名称、成功或失败状态和耗时，但 SHALL 不记录请求参数或工具结果正文。
4. IF 上游返回 JSON-RPC 错误 THEN 系统 SHALL 保留错误语义和可安全公开的消息，而不得把进程环境或内部路径拼入错误。

## 非功能需求

- **NFR-1（启动性能）**：每个上游的初始化和发现超时可配置为固定安全上限；默认上限不超过 10 秒。
- **NFR-2（隔离）**：每个配置拥有独立的 stdio 子进程和请求序列，单一上游故障不得遗留孤儿进程。
- **NFR-3（兼容性）**：首版在 Windows 支持含空格的绝对可执行文件路径及通用上游配置。
- **NFR-4（回归）**：未配置或全部停用上游时，现有 MCP 的工具目录、认证和运行时行为保持不变。

## 依赖关系

- `tokio::process`、异步 stdin/stdout 和 `serde_json` 用于 stdio JSON-RPC 客户端。
- 现有 `WorkspaceProfile`、数据存储、MCP listener、工具 registry、运行时 supervisor 和工作区配置页。
- 用户本机安装的上游 MCP 所需工具链，仅由上游进程使用。
