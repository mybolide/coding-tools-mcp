# 需求文档：本地 MCP 配置入口与自动挂载

## 功能概述

工作区可配置本机 stdio MCP，并在启动本应用的 MCP 服务及其公网隧道时，把已启用上游 MCP 的工具自动挂载到同一工具目录。本次移除机器特定的预填示例入口，避免把某台开发机的路径和环境变量带入通用配置界面。

## 范围边界

**In Scope**

- 移除本地 MCP 配置表单的机器特定预设按钮及其预设数据。
- 保留“新增 stdio MCP”入口、已有配置、工具发现和工具开关。
- 验证已保存且启用的本地 stdio MCP 会在每次 MCP 服务启动时初始化，并在公网隧道创建前挂载已公开工具。

**Out of Scope**

- 不迁移或删除现有工作区配置。
- 不改变既有上游 MCP、隧道供应商或核心工具的权限策略。

## 需求列表

### FR-1: 移除机器特定预填示例

**优先级:** Must

作为工作区管理员，我希望只看到通用的 stdio MCP 新增入口，以便手动填写适合本机的命令、参数和环境变量。

1. WHEN 打开本地 MCP 配置区 THEN 系统 SHALL 不显示任何机器特定预填示例按钮。
2. WHEN 新增本地 MCP THEN 系统 SHALL 创建无机器路径和无预设环境变量的通用 stdio 草稿。
3. WHEN 已存在上游配置 THEN 系统 SHALL 保持该配置不变，直到管理员自行保存修改。

### FR-2: 启动时自动挂载已启用上游工具

**优先级:** Must

作为远端 MCP 客户端使用者，我希望启动 MCP 服务后即可看到已启用本地 MCP 的公开工具，无需再次在客户端单独接入本机服务。

1. WHEN MCP 服务从停止状态启动 THEN 系统 SHALL 在启动监听器前初始化全部已启用上游 stdio MCP 并读取工具目录。
2. WHEN 公网隧道为该 MCP 服务建立 THEN 系统 SHALL 复用同一已初始化的工具目录，公开核心工具与上游已启用工具。
3. IF 任一上游初始化失败 THEN 系统 SHALL 报告错误状态且不创建不完整的 MCP 服务或隧道。

## 非功能需求

- **NFR-1（兼容性）:** 现有 `allowed_tools` / `disabled_tools` 配置语义不变。
- **NFR-2（安全）:** 本地 MCP 的命令和环境变量不因移除示例而被修改或泄露。

## 依赖关系

- 前端依赖 `UpstreamMcpForm` 的通用 stdio 配置模型。
- 自动挂载依赖 `UpstreamMcpManager::start` 与 `start_mcp_service` 的既有启动顺序。
