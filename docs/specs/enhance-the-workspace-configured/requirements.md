# 需求文档：本地 MCP 自动工具发现与启动可靠性

## 功能概述

工作区配置的本地 stdio MCP 应在启动或用户请求探测时自动读取其工具目录。远端默认可使用所有已发现工具，工作区所有者可在桌面端逐项关闭工具；关闭状态会保存并在服务重启后继续生效。同时，MCP 启动失败必须快速进入带明确原因的错误状态，不能一直显示“正在启动”。

## 术语定义

- **已发现工具**：上游 stdio MCP 在 `tools/list` 返回、且具有有效名称与输入 schema 的工具。
- **工具可见性**：某个已发现工具是否被合并到本应用对外的 `/mcp` 工具目录。
- **旧版白名单**：旧配置中的 `allowed_tools`；非空时表示用户此前明确选择了可公开工具。

## 范围边界

**In Scope**

- 自动发现已启用 stdio 上游的工具。
- 新建配置及没有旧版白名单的配置默认公开全部已发现工具。
- 在桌面端获取工具目录、展示工具名称/说明、为每项提供开关，并保存关闭项。
- 兼容已有非空 `allowed_tools`：保留其仅公开已选工具的语义，直到用户保存新的工具开关设置。
- 修复启动路径中同步等待异步上游初始化造成的服务卡在 starting 的问题，并显示安全、可操作的错误。

**Out of Scope**

- HTTP、SSE 或远程上游 MCP。
- 让远端 MCP 调用指定命令、参数或环境变量。
- 将上游环境变量迁移到密钥存储。

## 需求列表

### FR-1：自动发现和默认公开

**优先级:** Must

作为工作区所有者，我希望本地 MCP 自动读取上游工具，而不必手动填写工具名称。

#### 验收标准

1. WHEN 已启用 stdio 上游成功启动 THEN 系统 SHALL 执行 MCP 初始化和 `tools/list`，并缓存全部有效工具。
2. WHEN 配置没有旧版非空白名单且没有关闭项 THEN 系统 SHALL 公开全部已发现工具。
3. IF 上游工具目录无效、初始化失败或超时 THEN 系统 SHALL 终止该上游进程并使本次 MCP 启动失败。
4. WHILE 工具未在可见工具集合中 THEN 系统 SHALL 拒绝远端对该工具的调用。

### FR-2：逐项工具开关

**优先级:** Must

作为工作区所有者，我希望在图形界面逐项关闭已发现工具。

#### 验收标准

1. WHEN 我选择“获取工具” THEN 系统 SHALL 使用当前未保存的命令、参数和环境变量进行临时 stdio 探测，并返回安全的工具名称、说明和输入 schema。
2. WHEN 我关闭某项工具并保存 THEN 系统 SHALL 持久化该工具为关闭状态；运行中的 MCP SHALL 重新加载工具目录。
3. WHEN 我再次获取工具或重启 MCP THEN 系统 SHALL 默认启用新发现的工具，除非其名称已被持久化为关闭。
4. WHEN 新配置没有已发现工具目录 THEN 界面 SHALL 清晰提示用户先获取工具；保存仍不得泄露环境变量。

### FR-3：旧配置兼容

**优先级:** Must

作为已有用户，我希望原先手工白名单的安全范围不会在升级时突然扩大。

#### 骟收标准

1. WHEN 旧配置的 `allowed_tools` 非空且新关闭项字段不存在 THEN 系统 SHALL 继续仅公开旧白名单中的已发现工具。
2. WHEN 用户在新版界面保存已发现工具开关 THEN 系统 SHALL 转换为新的关闭项语义，并清除旧白名单。
3. WHEN 旧配置的白名单为空 THEN 系统 SHALL 采用新版默认全部公开语义。

### FR-4：启动状态和诊断

**优先级:** Must

作为工作区所有者，我希望启动失败时立即知道可采取的修复动作。

#### 验收标准

1. WHEN MCP 启动需要上游初始化 THEN 系统 SHALL 异步等待初始化，且不得在异步运行时中嵌套阻塞等待。
2. IF 上游启动、初始化、读取工具目录或绑定端口失败 THEN 系统 SHALL 在有限时间内将运行时状态设为 `error`，并返回安全的具体原因。
3. WHEN 启动成功 THEN 系统 SHALL 在报告 running 前确认本地监听器已启动，且上游目录已完成发现。
4. WHEN 错误发生 THEN 系统 SHALL 在工作区日志中记录安全诊断，不记录环境变量、参数或上游 stderr。

### FR-5：安全不变量

**优先级:** Must

1. WHILE OAuth、Bearer 或无认证模式生效 THEN 系统 SHALL 在调用上游工具前沿用现有外层认证。
2. WHEN 对外公开上游工具 THEN 系统 SHALL 使用 `<prefix>__<original_name>`，并拒绝与核心或其他上游工具冲突的名称。
3. WHEN 上游返回 `content`、`structuredContent` 或 `isError` THEN 系统 SHALL 保留这些 MCP 结果字段。

## 非功能需求

- **NFR-1（响应性）**：工具探测和启动各自最多等待 10 秒；应用主事件循环不得被阻塞。
- **NFR-2（兼容性）**：旧工作区数据能在没有迁移脚本的情况下反序列化。
- **NFR-3（安全）**：探测结果、公开目录和日志均不包含上游环境变量值。

## 依赖关系

- Tokio 子进程与异步 I/O。
- 现有 MCP listener、RuntimeSupervisor、WorkspaceProfile 和工作区配置页面。
- 用户本机提供的上游 MCP 及其所需工具链。
